# AI API、代码修改与安全标准

## 1. 接入方式

- 用户自行填写 API 地址、API Key 和模型名称。
- 首版按 OpenAI 兼容接口设计，后续再增加专用适配器。
- 未配置 API 时，手动编辑、预览、素材替换、撤销和版本恢复必须照常可用。
- API 配置可以有全局默认值；项目级覆盖属于后续能力。

## 2. 密钥处理

- API Key 不写入主题单元项目、HTML、CSS、JS、日志或版本快照。
- 本地保存时使用 Windows 可用的安全凭据存储；界面只显示掩码。
- 日志不得记录完整请求头、密钥或完整项目源码。
- AI 请求发送前应告诉用户会发送哪些项目内容。

## 3. AI 修改流程

```text
用户描述需求
  → 选择必要的项目范围
  → AI 分析代码和页面关系
  → 返回修改说明与补丁
  → 在隔离预览中运行
  → 用户查看差异并测试
  → 用户确认应用
  → 写回前创建快照
```

AI 的主要职责是复杂 JavaScript 逻辑，例如答题、计分、条件分支、进度、弹窗、媒体和跨页面状态。字体、位置和简单素材调整优先由用户在编辑器中完成。

## 4. 补丁规则

- AI 必须返回受影响文件、修改说明和可审阅的差异。
- 默认只修改必要文件；禁止无理由格式化整个项目。
- 不执行 AI 返回的桌面命令或未知脚本。
- 应用失败时自动回滚到应用前快照，并保留错误信息。
- 用户可以拒绝补丁、逐文件查看或恢复上一版本。
