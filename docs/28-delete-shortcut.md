# 删除键修复（2026-10-22）

## 发现的问题

- 画布pointerdown阻止默认行为后，焦点可能仍留在编辑器属性输入框。Delete/Backspace被当作输入框编辑，未进入素材删除。
- 新增图片使用明确的出现范围。旧删除只是写display:none，渲染时又被出现范围的display:block覆盖。
- 画布键盘删除通过父窗口的React选中状态再回传，存在选中状态不同步的窗口；多选被直接禁止。
- 最近打开的webp课件使用CoursewareApp.getState().phase，原适配器只读取CoursewareDebug.getState().name，因而默认当前画面删除被范围检查阻止。

## 修改

点击/拖动选框、尺寸点或新增图片后，显式把键盘焦点交给画布；属性输入框内的文本编辑及组合快捷键仍保留。失焦属性提交只刷新原选中对象，不重新抢回选区。

画布Delete和Backspace直接使用画布选区；右侧删除按钮与外层快捷键发出统一删除命令，画布完成后通知界面。单选、组合与多选共同检查范围、产生一次布局快照，可整批撤销。删除成功后才清空选中状态。

删除保存为有画面选择器及设备范围的显示遮罩，display:none在已有出现范围之后应用，避免被强制显示复原。遮罩的数据结构可由旧版已保存布局运行代码解释；普通出现范围调整保留遮罩，撤销恢复原快照。未改变旧课件的绘制运行代码。

画面适配器增加CoursewareApp.phase支持，并标记版本。保存布局时更新独立的画面适配脚本，使编辑器和独立网页都能读取相同业务状态。

本次不替用户删除实际素材，不修改课件文件。完成CJS、内嵌桥接脚本、TypeScript编译和Vite构建；未添加或运行测试套件，未完成实际按键与鼠标交互验收。
