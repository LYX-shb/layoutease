# 测试中意外重置（2026-10-22，0.1.5）

用户反馈一直处于测试模式、没有切换模式时，课件中途回到开始。

确认可复现的触发链是：课件目录的 HTML、JS、CSS 或素材文件变化 → 项目监听通知 → 前端在没有草稿或选中元素时递增 previewNonce → iframe 重建，课件内存中的进度丢失。此前没有把测试模式列入禁止自动刷新的条件。

现在测试过程中收到文件变更只显示原有更新提示，由用户点击“读取最新文件”刷新。在编辑和定格状态下既有的进度保护继续生效。初次编辑、尚无操作时的自动读取仍保留。没有改动界面布局、课件逻辑或计时暂停算法。

另外修正模式切换的独立重置路径：“保存并切换”之前的回调捕获了旧 dirty 状态，保存成功仍重建 iframe。现在对回调明确传递是否放弃草稿，仅主动放弃草稿时重新读取页面以清除未保存的预览修改；保存后继续测试或等待定格沿用当前文档。

## 回归证据

- 修改前，在临时项目中推进到测试中途，写入一个 CSS 文件，页面的 progressMarker 被清空，复现重置。
- 修改后同一场景保持同一页面、测试模式和当前画面；只显示文件更新提示。
- 暂停、拖动素材，再使用“保存并切换”继续测试，文档标记和当前画面保留。
- 点击“读取最新文件”仍会按要求刷新并载入新内容。
- TypeScript 和 Vite 生产构建、`node --test` 的 54 项检查通过。
- 桌面版本已替换为 0.1.5.0，安装 ASAR 与构建产物哈希一致，安装后已检查新界面正常加载并重新打开桌面快捷方式。

专项检查：使用 Electron 运行 `scripts/check-preview-playback.cjs --check-progress`。日志位于 `release/progress-before.*.log` 和 `release/progress-after.*.log`。原课件文件未被此检查改写。
