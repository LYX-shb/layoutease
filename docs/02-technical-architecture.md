# 技术架构与实现标准

## 1. 推荐技术基线

- 桌面端：Electron，目标平台为 Windows。
- 应用界面：React + TypeScript + Vite。
- 状态管理：优先使用轻量、可追踪的单向状态；具体库在实现阶段确定，但编辑状态必须可序列化。
- 预览：隔离的本地预览会话，使用 iframe 或受控 BrowserView 承载主题单元网页。
- 文件处理：仅通过受控文件服务读取和写回用户选择的项目目录。
- AI 接口：OpenAI 兼容的 HTTP API，服务商、地址、模型和密钥由用户配置。

当前仓库为空项目，因此第一版直接采用以上技术基线。后续如果更换技术基线，必须在文档中记录理由和迁移影响。

## 2. 目录边界建议

```text
app/                 桌面应用入口和窗口管理
src/                 React 界面、状态和编辑器逻辑
src/preview/         本地预览、通信和刷新
src/project/         项目扫描、元素识别、文件写回
src/history/         撤销、重做、版本快照
src/ai/              API 配置、上下文整理、补丁应用
docs/                产品和开发标准
```

## 3. 项目识别标准

首版按普通 HTML/CSS/JS 项目处理：

- 优先识别用户选择目录下的 `index.html`。
- 若不存在，要求用户选择入口 HTML，不猜测并覆盖文件。
- 相对资源引用必须在预览和写回前保持可解析。
- 所有可编辑元素使用稳定的 `data-editor-id`；找不到标识的元素可预览，但首版不保证可安全写回。
- 不改变原项目的路由、打包和构建方式。

推荐标识示例：

```html
<h1 data-editor-id="unit-title">主题单元标题</h1>
<button data-editor-id="next-button">下一步</button>
```

## 4. 编辑数据流

```text
项目文件
  → 扫描与解析
  → 受控编辑状态
  → 预览运行时
  → 用户确认
  → 生成最小文件补丁
  → 写回前快照
  → 保存并刷新预览
```

编辑器不得把画布当前像素位置直接当成唯一数据源。位置、字号和内容必须映射到可追踪的 CSS/HTML 修改记录，便于撤销和恢复。

## 5. 文件写回与恢复

- 修改前创建快照；写回采用临时文件、校验、替换的顺序。
- 写回失败时保留原文件，不执行部分覆盖。
- 撤销和重做作用于编辑操作；版本恢复作用于完整项目快照。
- 版本快照默认存放在应用本地数据目录，并以项目路径哈希关联，避免污染用户项目。
- 用户明确保存前，所有修改都视为草稿。

## 6. 预览安全

- 预览内容与桌面应用主进程隔离。
- 不允许预览网页直接访问 Electron Node 能力。
- 文件访问限制在用户选择的项目目录内。
- AI 返回的代码只能进入差异审阅和沙盒预览流程，不能静默执行桌面命令。
