# 购物篮组件与真实画面切换修复（0.1.9）

## 问题与原因

0.1.8 的跨画面验证主要使用同一素材的面板，并直接替换 SVG。用户实际编辑的购物篮在六个画面中使用不同图片、不同透明留白，食品和前沿还是独立图层；按同一图片关联不能覆盖这一组件。课件业务切换还会动态隐藏原始标题层，导致原来的画面签名失效。

新增标题 SVG 覆盖整幅画布，虽然只在局部绘制内容，空白区域仍被编辑器当作一个整体选中。这解释了更新后仍出现“点哪里都是整张图”的情况。

## 修复

- 在核对六组节点、素材哈希与图层结构后，为此课件的购物篮建立稳定组件，将篮内食品与前沿一起调整。用图片实际可见区域定义尺寸，避免透明留白改变视觉大小。
- 画面识别忽略业务运行时改变的显示属性，并升级标记所有权，兼容旧版保存脚本。
- 同步记录保存后再次加载、撤销、改变范围时保留几何数据；旧版原始节点记录迁移至稳定组件。
- 素材选择跳过多对象 SVG 的空白视口，保留对其具体图层的选择和小图标整体选择。
- 提供显式修复脚本 `scripts/repair-basket-component.cjs`，先备份完整 HTML、检查并发写入，再迁移原购物篮位置记录，同时固定位置和尺寸到全部画面。其他记录与课件业务源码保留。

购物篮适配仅在已验证的六画面素材、节点和结构完全匹配时启用；其他课件不按位置猜测组件关系。

## 验证

- `node --test`：67 项通过。
- 元素选择：19 项通过，包含真实鼠标、标题覆盖层空白处穿透、拖动、保存重载和交互热区。
- 购物篮同步：8 项通过，包含保存旧脚本兼容、六画面几何、移动缩放、撤销、指定画面范围和脱离编辑器运行。
- 真实业务链路：空篮、放糖果、放饼干、同时放入、答错、答对、重来。每一步核对完整购物篮可见边界和食品归属，不直接修改画面状态代替业务操作。

用户课件只在本机迁移并保留备份，不提交到源码仓库。
