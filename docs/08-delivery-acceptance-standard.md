# 第一版交付标准

更新时间：2026-10-04

这份文件是第一版能否交付的硬标准。没有通过“必须项”的版本只能算开发中，不能称为可交付版本。

## 一、版本定义

### A. 演示版

能打开示例项目并展示编辑器界面。演示版只用于确认方向，不能用于编辑真实项目，也不能承诺保存可靠。

### B. 第一版基础可交付版本（MVP-Manual）

用户可以把一个真实的 HTML/CSS/JS 主题单元放进编辑器，完成常见页面微调，保存后重新打开仍然保留；修改过程中出现错误可以撤销或恢复。第一版基础交付必须通过下面第 1～6 项，不要求覆盖所有网页写法，但不能静默损坏源文件。

### C. 第一版完整可交付版本（MVP-AI）

在 MVP-Manual 通过后，再加入第 7 项用户自带 API 的 AI 助手。AI 不能用来掩盖手动编辑器的保存、撤销或恢复问题；基础编辑未稳定前不进入 AI 开发。

## 二、必须通过的功能验收

### 1. 项目打开与预览

- 选择一个包含 `index.html`、CSS、JS 和素材的文件夹即可打开。
- 相对路径图片、样式和脚本正常加载。
- 项目原文件不会因为打开而被改写。
- 找不到入口文件时显示明确原因，并可以返回重新选择。

**验收操作：**打开一个包含图片、按钮和页面跳转的真实主题单元，预览效果与浏览器直接打开基本一致。

### 2. 单页面可视化微调

- 点击页面中的标题、正文、按钮、图片等可见元素即可选中。
- 不要求用户手动给 HTML 添加 `data-editor-id` 或其他技术标识。
- 拖动后预览立即变化，点击保存后源文件确实变化。
- 可以修改文字、字号、位置、宽高、颜色和常用间距。
- 保存成功必须有明确反馈，例如“已保存到 index.html”。
- 关闭项目后重新打开，修改仍然存在。

**验收操作：**选中标题改文字和字号，拖动按钮，替换一张图片，保存，关闭并重新打开；三项修改都必须保留。

### 3. 素材替换

- 图片、图标至少可以替换并写入项目内的素材目录。
- 替换后引用路径正确，从项目根目录重新打开时仍能加载。
- 替换失败时原素材保持不变。

### 4. 电脑、平板、手机适配

- 提供电脑、平板、手机竖屏、手机横屏预览尺寸。
- 手机方向必须明确选择竖屏或横屏，不能依赖自动猜方向。
- 在每个尺寸下都能看到页面是否溢出、遮挡或无法点击。
- 用户在不同尺寸下做出的适配调整，保存后重新打开仍能复现。

### 5. 多页面与真实交互

- 可以识别项目中的多个 HTML 页面并切换编辑。
- 测试模式下，原网页的下一页、返回、按钮、弹窗等交互可以运行。
- 编辑模式和测试模式必须有明显区分，避免测试点击误改页面。
- 当前页面保存到当前页面文件，不能误写其他页面。

### 6. 撤销、重做与版本恢复

- 连续至少 20 次文字、位置、字号或素材修改可以逐步撤销和重做。
- 保存前自动创建可恢复快照。
- 可以从版本列表选择旧版本恢复。
- 恢复失败时保留当前文件，不能把项目变成空文件或半截文件。

### 7. 用户自带 API 的 AI 助手

- 用户可以填写自己的 API 地址、密钥和模型；未配置时普通编辑仍可用。
- AI 用于复杂 JavaScript 逻辑，例如页面跳转、答题判断、计分、弹窗和媒体控制。
- AI 修改前必须展示修改说明和代码差异。
- 用户确认前不得写入项目文件。
- AI 修改后可以在预览中运行；失败或不满意时可以恢复到修改前版本。
- 密钥不能写入项目 HTML、CSS、JS 或日志。

## 三、直接判定“不合格”的问题

出现以下任一情况，版本不能交付：

- 点击保存没有反馈，用户无法知道是否写入成功。
- 需要用户手动打开 HTML 添加标识才能保存常见元素。
- 保存后重新打开修改丢失。
- 保存或恢复会误改其他元素、其他页面或整份项目文件。
- 撤销、重做、版本恢复会造成空文件、乱码或页面无法加载。
- AI 未经确认直接覆盖项目文件。
- 测试模式点击网页按钮会意外移动或修改元素。

## 四、第一版明确暂缓的内容

- 课程目录、章节树、页面排序和模板市场。
- 任意前端框架的完全兼容。
- 自动理解所有未知 JavaScript 并把它转换成可视化配置。
- 在线协作、云端项目和自动发布。
- 复杂时间轴、多人权限和学习数据后台。

这些内容可以在第一版稳定后再排期，不能阻塞单主题单元编辑交付。

## 五、每次开发的交付记录格式

每完成一个功能必须写清楚：

1. 本次通过了哪一条验收标准。
2. 修改了哪些文件。
3. 用户如何用 3～5 步复现并验收。
4. 仍然存在什么限制。
5. 下一步只做哪一条标准。

如果本次功能没有通过对应验收，不继续扩展下一个大功能，先修复当前问题。
